# 星屑灯阵 · 唯美版试玩接入方案

## 1. 目标与合格标准
为「奥觅」做一个**极其唯美**的 4×4 灯阵解谜原型，并接入复玩的版本 / 试玩流程。视觉是第一优先级，玩法保持最小可玩。

合格标准（可判定，是/否）：
- `GET <预览地址>/playtest/` 返回 200，页面无控制台报错。
- 首屏在 1440×900 与 390×844 下无横向滚动、无文字溢出，格子点击区域 ≥44px。
- 背景至少两层动画（极光 + 星尘），灯片点亮态有可见光晕，点击有涟漪反馈，通关有独立过渡。
- 第一关可玩通并出现「夜色归寂」通关面板；点「继续寻星」进入第二关。
- 在复玩里保存 0.1.0 版本后，版本卡链接可直接打开游戏。
- `prefers-reduced-motion` 下环境动画停止，游戏仍可正常操作。

## 2. 现状分析
- 技术栈：React 19 + Vite + TypeScript；项目 / 版本 / 试玩存在浏览器 localStorage（`replay-state-v1`）。
- 版本表单：[App.tsx](file:///workspace/src/App.tsx#L202-L246)，版本号、可玩链接（`type="url"`，必填）、本版修改均必填；保存逻辑 [App.tsx](file:///workspace/src/App.tsx#L579-L596)。
- 试玩表单：[App.tsx](file:///workspace/src/App.tsx#L248-L289)；创建前必须先选版本（[App.tsx](file:///workspace/src/App.tsx#L598-L605)）。
- 当前工作区没有 `public/`、`node_modules/`、`dist/`，无运行中的预览进程；执行前需 `npm install`。
- 数据边界：项目在你的浏览器里，我无法替你写入 localStorage；界面保存动作由你完成，我给出逐字段值并做游戏侧验证。

## 3. 视觉概念：「星屑灯阵」
主题贴合「奥觅」的寻找意象：夜航星图。深空墨青作底，极光薄雾缓慢流动，星尘上浮；16 盏灯是悬浮的琉璃星片——亮时暖金内发光，灭后只留冷银轮廓。点击泛起涟漪，通关时星尘归拢、标题浮现「夜色归寂」。

设计原则：暗、静、少而精；靠光晕层次和留白出质感，不堆装饰、不用外链素材。

### 3.1 设计令牌（写进 `index.html` 的 `:root`）
```
--ink-0: #05080d;      /* 最深背景 */
--ink-1: #0a1218;
--ink-2: #102028;
--mist:  #1a2f33;      /* 极光青 */
--star:  #ffd9a3;      /* 暖金灯光 */
--star-core: #fff3d6;  /* 灯芯 */
--glow:  rgba(255, 183, 94, 0.55);
--silver:#9fb4b6;      /* 冷银描边 */
--line:  rgba(214, 232, 226, 0.16);
--paper: #f3efe4;      /* 正文米白 */
--serif: "Songti SC", "Noto Serif SC", "Source Han Serif SC", serif;
--sans:  "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
```

### 3.2 分层与动效
1. **背景层**：三组 radial-gradient（深青 / 墨蓝 / 暗金）叠底；两条极光带用 CSS 渐变 + `filter: blur(60px)`，60–90s 缓慢漂移；最上层内联 SVG `feTurbulence` 噪点，透明度 0.05。
2. **星尘层**：`<canvas>`，按 devicePixelRatio 缩放，50–70 个微粒子缓慢上浮、明灭；`prefers-reduced-motion` 时静止，页面隐藏时暂停 `requestAnimationFrame`。
3. **舞台**：最大宽度 520px 居中；标题「星屑灯阵」宋体 44–52px、字距 0.18em；副题「奥觅 · 解谜益智测试」小号字；一条 1px 金色细线分隔。
4. **文案**：诗性一句 + 机制一句，兼顾唯美与可理解：
   - 诗性：「轻触一星，相邻四盏随之明灭。」
   - 机制：「目标：让 16 盏灯全部熄灭。」
5. **灯片**：4×4，gap 16–18px，圆角 16px，`aspect-ratio: 1`。
   - 熄灭：半透明墨青玻璃、1px 冷银描边、内阴影，像沉入夜色。
   - 点亮：暖金 radial-gradient 灯芯 + 三层 `box-shadow` 光晕 + 顶部高光；`transition: 220ms cubic-bezier(.2,.8,.2,1)`。
6. **交互**：hover 上浮 2px、描边变亮；按下 `scale(.97)`；点击在指针位置生成 500ms 金色涟漪（CSS 变量 `--x/--y` + keyframe）；同时由 canvas 散出 6–10 粒金色微尘。
7. **状态栏**：`CHAPTER 01 / 03` 小号大写英文 + 中文「第 1 章 · 初夜」；步数用 `font-variant-numeric: tabular-nums`。
8. **通关**：「夜色归寂」标题；网格呼吸 1.2s，金色粒子自下而上，极光增强；毛玻璃面板淡入（`backdrop-filter: blur(20px)`），按钮「继续寻星」。
9. **章节切换**：400ms 交叉淡出 / 淡入，避免闪跳。
10. **可访问性**：每格 `<button>` + `aria-label="第 r 行第 c 列，亮/灭"` + `aria-pressed`；`focus-visible` 金色描边；状态变化用 `aria-live="polite"`；正文对比度 ≥4.5:1。

### 3.3 文件结构
只新增两个文件，不改应用代码、不加依赖、不动服务端。

**`public/playtest/index.html`**
- 语义结构 + 全部 CSS + `<canvas>` + 通关面板 + `?dev=1` 才显示的「测试：自动通关」。
- 不引用任何外链字体、图片、CDN；断网也能完整呈现。
- `lang="zh-CN"`、viewport、`theme-color`。

**`public/playtest/game.js`**
- 逻辑：
  - `SIZE = 4`，16 格；`false` 熄灭，`true` 点亮。
  - 三关翻转次数 `[3, 5, 7]`，固定种子 `[20261123, 20261124, 20261125]`，题目可复现。
  - `toggle(grid, index)`：翻转自身与上下左右，越界忽略。
  - `createLevel(flips, seed)`：全灭盘开始，用 mulberry32 取不重复格子翻转；若回到全灭则补一次未用格子；`solution` 为这些格子的反序（灯阵翻转自逆）。
  - `isSolved(grid)`：16 格全灭。
- 交互：点击翻灯、步数 +1、胜利判定；重置本关；重新开始；下一关；通关后禁用网格。
- 视觉：涟漪、微尘粒子、章节过渡、星尘 canvas；统一受 `prefers-reduced-motion` 控制。
- `?dev=1`：「测试：自动通关」按 `solution` 依次翻转并触发胜利；手动点击仍保留，用于验证步数与翻转范围。

### 3.4 不改动
- 不修改 `App.tsx`、`domain.ts`、`server/`、测试配置。
- `public/` 是 Vite 默认静态目录，构建会复制到 `dist/playtest/`；这是同源访问的实现方式。若以后不想随生产构建发布，删除该目录或关闭 `copyPublicDir`，不影响应用逻辑。

## 4. 界面填写清单（你在当前页面操作）
可玩链接 = 当前预览地址 + `/playtest/`。若预览是 `http://127.0.0.1:5199`，填 `http://127.0.0.1:5199/playtest/`。

「保存可玩版本」弹窗：
- 版本号：`0.1.0`
- 可玩链接：`<当前预览地址>/playtest/`
- 本版修改：`首个可玩原型：4×4 星屑灯阵，点击翻转自身与上下左右，3 关递进，目标为熄灭全部灯光；暂无撤销与计时。`

「发起试玩」表单：
- 试玩标题：`星屑灯阵 · 首次体验测试`
- 评测目标：`验证中学生不看解释能否理解目标与操作，并完成第一关`
- 试玩任务：`打开游戏链接，不看作者说明，尝试完成第一关；如果卡住，记下卡住前你在想什么。`
- 目标人数：`3`

试玩观察点（后续写证据帖对照）：
- 是否理解「熄灭全部灯光」这个反直觉目标。
- 是否误解点击只翻转自己、不知道会带动上下左右。
- 卡在第几关、卡住时是否反复点同一格。
- 无撤销、无计时是否造成挫败或催促感。
- 手机窄屏下点击精度与误触。
- 唯美氛围是否帮助沉浸，还是让规则更难读。

## 5. 假设与决策
- 视觉方向定为「深空星辉」，因为最贴合「奥觅」的寻找意象；方向不合时只改 CSS 令牌与动效参数，不动玩法逻辑。
- 「唯美」是主观判断：我用可判定的视觉验收项兜底，最终由你看截图终审。
- 不引入图片 / 字体 / 音频素材，全部用 CSS、SVG、Canvas 生成，保证离线与加载速度。
- 不做计时、撤销、账号、数据上报；保持最小可玩。
- 不接服务端身份 / 试玩码；那是另一条链路。

## 6. 验证步骤
1. `npm install`（当前缺依赖）。
2. `npm run build`，确认 `dist/playtest/index.html` 与 `dist/playtest/game.js` 存在。
3. 启动 `npx vite preview --port 5199 --host 0.0.0.0`（端口占用则用实际端口）。
4. `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5199/playtest/` 期望 `200`。
5. 浏览器打开 `/playtest/?dev=1`：
   - 手动点一格：步数 0→1，该格与相邻格翻转，涟漪可见。
   - 点「测试：自动通关」：出现「夜色归寂」。
   - 点「继续寻星」：状态变为「第 2 / 3 关」。
6. 视觉截图：1440×900 与 390×844 各一张，检查无溢出、光晕层次、星尘与极光存在；截图交给用户终审。
7. 用系统「减少动态效果」或代码开关验证 `prefers-reduced-motion` 分支：环境动画停止、游戏仍可玩。
8. 在复玩里按第 4 节保存版本，确认版本卡链接可点开。

## 7. 回退判定
- `/playtest/` 返回 404：先查 `dist/playtest/` 是否生成；未修复不交付。
- 构建失败、控制台报错、或移动端出现横向滚动：先修；修不好则退回纯 CSS 背景版本（去掉 canvas 粒子）再交付。
- 每次构建后检查一次：页面 200、三关可进入、移动端无横向滚动；任一不满足即视为回退。

## 8. 风险与边界
- `public/` 会随生产构建发布；这是同源方案的代价。
- Canvas 粒子在低端设备可能掉帧：粒子上限 70、页面隐藏时暂停、reduced-motion 直接停用。
- 链接必须用实际预览地址；端口变化后旧链接失效。
- 无后端，试玩记录仍保存在各自浏览器，不能跨设备汇总。
