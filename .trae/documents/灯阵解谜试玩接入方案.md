# 灯阵解谜试玩接入方案

## 1. 目标与合格标准
为「奥觅」项目做一个可直接试玩的益智解谜原型，并接入复玩的版本 / 试玩流程。

合格标准（可判定，是/否）：
- `GET <预览地址>/playtest/` 返回 200，页面无控制台报错。
- 第一关可以玩通并出现通关面板；点「下一关」能进入第二关。
- 在复玩里保存 0.1.0 版本后，版本卡上的链接能直接打开该游戏。
- `npm run build` 后 `dist/playtest/` 仍存在且可访问。

## 2. 现状分析
- 技术栈：React 19 + Vite + TypeScript；项目 / 版本 / 试玩全部存在浏览器 localStorage（键 `replay-state-v1`）。
- 版本表单：[App.tsx](file:///workspace/src/App.tsx#L202-L246)，版本号、可玩链接（`type="url"`，必填）、本版修改均为必填；保存逻辑在 [App.tsx](file:///workspace/src/App.tsx#L579-L596)。
- 试玩表单：[App.tsx](file:///workspace/src/App.tsx#L248-L289)；创建前必须先选一个版本（[App.tsx](file:///workspace/src/App.tsx#L598-L605)）。
- 当前工作区没有 `public/`、`node_modules/`、`dist/`，也没有正在运行的预览进程；执行阶段需要先安装依赖。
- 关键边界：项目数据在你自己的浏览器里，我无法替你写入 localStorage。因此我会交付游戏与可访问链接，并给出逐字段填写值；界面上的保存动作需要你在当前页面完成。

## 3. 改动内容
只新增两个静态文件，不改应用代码、不加依赖、不动服务端。

### 3.1 新增 `public/playtest/index.html`
- 中文单页，`lang="zh-CN"`，含 viewport，标题「灯阵解谜 · 奥觅试玩」。
- 结构：
  - 顶部：`灯阵 · 测试版` 与 `奥觅 / 解谜益智测试`。
  - 规则一句话：「点击一盏灯，会翻转它和上下左右的灯。目标：让 16 盏灯全部熄灭。」
  - 状态栏：`第 1 / 3 关`、`步数 0`。
  - 4×4 按钮网格。
  - 操作：`重置本关`、`重新开始`。
  - 通关面板（默认隐藏）：`第 N 关完成`、本关步数、`下一关` / `再从第一关开始`。
- 内联 CSS，配色沿用复玩的深绿 / 米白；不引用任何外链字体、图片或 CDN。
- 仅在 URL 带 `?dev=1` 时显示「测试：自动通关」按钮，正式试玩不可见。

### 3.2 新增 `public/playtest/game.js`
- 纯逻辑函数 + DOM 绑定，ES module，无依赖。
- 常量与关卡：
  - `SIZE = 4`，共 16 格；`false` = 熄灭，`true` = 点亮。
  - 三关翻转次数 `[3, 5, 7]`，固定种子 `[20261123, 20261124, 20261125]`，保证每次打开题目一致、可复现。
- `toggle(grid, index)`：翻转自身与上下左右，越界忽略。
- `createLevel(flips, seed)`：
  - 从全灭盘开始，用 mulberry32 从 16 格中取不重复格子翻转 `flips` 次。
  - 若结果恰好回到全灭，再补一次未使用的格子，确保开局不是已通关。
  - `solution` 记录这些格子（反序即可解，灯阵翻转自逆）。
- `isSolved(grid)`：16 格全为 `false`。
- 交互：
  - 点击格子翻转并 `moves + 1`，随后检查胜利。
  - `重置本关` 恢复本关初始盘与 0 步；`重新开始` 回第一关。
  - 通关后禁用网格，显示面板；`下一关` 进入下一关，第三关后回到第一关。
- 可访问性：每格是 `<button>`，`aria-label="第 r 行第 c 列，亮/灭"`，`aria-pressed` 同步状态；焦点样式可见；键盘可操作。
- `?dev=1`：「测试：自动通关」按 `solution` 依次翻转并触发胜利，用于自动验证通关分支；同时保留手动点击以验证步数与翻转范围。

### 3.3 不改动
- 不修改 `App.tsx`、`domain.ts`、`server/`、测试配置。
- `public/` 是 Vite 默认静态目录，`npm run build` 会整体复制到 `dist/playtest/`；这是同源访问的实现方式。若以后不想随生产构建发布，删除该目录或关闭 `copyPublicDir` 即可，不影响应用逻辑。

## 4. 界面填写清单（你在当前页面操作）
把当前预览地址后面拼上 `/playtest/` 作为可玩链接。若预览是 `http://127.0.0.1:5199`，则填 `http://127.0.0.1:5199/playtest/`。

「保存可玩版本」弹窗：
- 版本号：`0.1.0`
- 可玩链接：`<当前预览地址>/playtest/`
- 本版修改：`首个可玩原型：4×4 灯阵解谜，点击翻转自身与上下左右，3 关递进，目标为熄灭全部灯光；暂无撤销与计时。`

「发起试玩」表单：
- 试玩标题：`灯阵解谜 · 首次体验测试`
- 评测目标：`验证中学生不看解释能否理解目标与操作，并完成第一关`
- 试玩任务：`打开游戏链接，不看作者说明，尝试完成第一关；如果卡住，记下卡住前你在想什么。`
- 目标人数：`3`

试玩时重点观察（供后续写证据帖对照）：
- 是否理解「熄灭全部灯光」这个反直觉目标。
- 是否误解点击只翻转自己、不知道会带动上下左右。
- 卡在第几关、卡住时是否反复点同一格。
- 无撤销、无计时是否造成挫败或催促感。
- 手机窄屏下格子点击精度与误触。

## 5. 假设与决策
- 「奥觅」项目已存在于你的浏览器；本轮不重建、不覆盖。
- 游戏同源托管在现有预览服务下；外部测试者需能访问同一预览地址，这超出本轮本地 MVP 范围。
- 不做计时、撤销、账号、数据上报；保持最小可玩原型，问题留给试玩暴露。
- 不接服务端身份 / 试玩码；那属于另一条链路，本轮不混入。

## 6. 验证步骤
1. `npm install`（当前缺依赖）。
2. `npm run build`，确认 `dist/playtest/index.html` 与 `dist/playtest/game.js` 存在。
3. 启动 `npx vite preview --port 5199 --host 0.0.0.0`（若端口被占用则用实际端口）。
4. `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:5199/playtest/` 期望 `200`。
5. 浏览器打开 `/playtest/?dev=1`：
   - 手动点一格：步数 0→1，该格与相邻格状态翻转。
   - 点「测试：自动通关」：出现「第 1 关完成」。
   - 点「下一关」：状态栏变为「第 2 / 3 关」。
6. 按第 4 节在复玩里保存版本，回到「项目与版本」确认版本卡链接可点开游戏。

## 7. 回退判定
- `/playtest/` 返回 404：先查 `dist/playtest/` 是否生成；未修复不交付。
- 构建失败或页面控制台报错：删除 `public/playtest/`，改用独立端口方案，不带着报错交付。
- 观察频率与阈值：每次构建后检查一次 `/playtest/` 是否为 200、三关是否都能进入；任何一关不可进即视为回退。

## 8. 风险与边界
- `public/` 会随生产构建发布；这是同源方案的代价。
- 链接必须使用实际预览地址；端口变化时旧链接失效。
- 无后端，试玩记录仍保存在各自浏览器，不能跨设备汇总。
